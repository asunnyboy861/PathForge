# PathForge 改进计划 - OpenAI API 自定义配置

## 一、需求描述

### 1.1 背景

当前 PathForge 仅支持 OpenAI 官方 API，存在以下限制：
- 只能使用 `https://api.openai.com/v1/chat/completions` 作为请求地址
- 只能使用硬编码的 `gpt-4o-mini` 模型
- 无法使用第三方兼容服务（DeepSeek、Azure OpenAI、智谱AI等）
- 无法使用本地部署的 LLM 服务（Ollama、vLLM等）

### 1.2 需求目标

支持用户自定义配置：
1. **Base URL**：自定义 API 请求地址
2. **Model ID**：自定义模型标识符
3. **预设配置**：提供常用服务商的快捷配置选项
4. **连接测试**：验证配置是否有效

### 1.3 用户价值

| 用户场景 | 解决方案 | 价值 |
|----------|----------|------|
| 成本优化 | 使用更便宜的模型 | 降低使用成本 50-90% |
| 区域访问 | 使用国内镜像或 Azure | 解决网络访问问题 |
| 模型选择 | 根据任务选择不同模型 | 灵活性和成本控制 |
| 隐私合规 | 使用企业内部部署的 LLM | 满足数据合规要求 |
| 服务稳定性 | 多 API 提供商备份 | 避免单点故障 |

#### 3.2.1 AIConfiguration 模型

```swift
// Services/AIConfiguration.swift

import Foundation

struct AIConfiguration: Codable, Equatable {
    var apiKey: String = ""
    var baseURL: String = "https://api.openai.com/v1/chat/completions"
    var modelID: String = "gpt-4o-mini"
    
    static let `default` = AIConfiguration()
    
    static let presets: [AIPreset] = [
        AIPreset(name: "OpenAI", 
                 baseURL: "https://api.openai.com/v1/chat/completions", 
                 modelID: "gpt-4o-mini"),
        AIPreset(name: "DeepSeek", 
                 baseURL: "https://api.deepseek.com/chat/completions", 
                 modelID: "deepseek-chat"),
        AIPreset(name: "Azure OpenAI", 
                 baseURL: "", 
                 modelID: "", 
                 isCustom: true),
        AIPreset(name: "Ollama (Local)", 
                 baseURL: "http://localhost:11434/v1/chat/completions", 
                 modelID: "llama3")
    ]
    
    var isConfigured: Bool {
        !apiKey.isEmpty && !baseURL.isEmpty && !modelID.isEmpty
    }
}

struct AIPreset: Identifiable, Equatable {
    let id = UUID()
    let name: String
    let baseURL: String
    let modelID: String
    let isCustom: Bool
    
    init(name: String, baseURL: String, modelID: String, isCustom: Bool = false) {
        self.name = name
        self.baseURL = baseURL
        self.modelID = modelID
        self.isCustom = isCustom
    }
}
```

```swift
final class OpenAIService {
    private let configuration: AIConfiguration
    
    init(configuration: AIConfiguration) {
        self.configuration = configuration
    }
    
    func complete(prompt: String) async throws -> String {
        guard let url = URL(string: configuration.baseURL) else {
            throw OpenAIError.invalidBaseURL
        }
        
        var request = URLRequest(url: url)
        request.httpMethod = "POST"
        request.setValue("Bearer \(configuration.apiKey)", forHTTPHeaderField: "Authorization")
        request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        
        let body: [String: Any] = [
            "model": configuration.modelID,  // 使用配置的模型
            "messages": [
                ["role": "system", "content": "You are an expert learning path designer. Always respond with valid JSON only."],
                ["role": "user", "content": prompt]
            ],
            "temperature": 0.7,
            "max_tokens": 4096
        ]
        // ...
    }
    
    enum OpenAIError: LocalizedError {
        case invalidBaseURL      // 新增错误类型
        case invalidResponse
        case noContent
        
        var errorDescription: String? {
            switch self {
            case .invalidBaseURL: "Invalid API URL. Please check your configuration."
            case .invalidResponse: "Invalid response from AI service"
            case .noContent: "No content in AI response"
            }
        }
    }
}
```

## 四、代码复用与最小化原则

### 4.1 复用现有模式

| 现有模式 | 复用方式 |
|----------|----------|
| `SettingsViewModel` 存储模式 | 直接扩展，不创建新的 ViewModel |
| `UserDefaults` 存储机制 | 复用现有存储方式，添加新键名 |
| `didSet` 属性观察器 | 复用现有自动保存机制 |
| `@Observable` 宏 | 复用现有响应式模式 |

### 4.2 避免重复代码

**不创建**：
- ❌ 新的 `AIConfigurationViewModel`（复用 `SettingsViewModel`）
- ❌ 新的存储管理类（复用 `UserDefaults`）
- ❌ 新的配置验证服务（在 `OpenAIService` 中处理）

**创建**：
- ✅ `AIConfiguration` 结构体（数据模型，轻量级）
- ✅ `AIPreset` 结构体（预设配置，不可变）

### 4.3 三次法则应用

当前不满足"三次法则"：
- `baseURL` 和 `modelID` 只在 `OpenAIService` 中使用一次
- 不需要额外抽象层

如果未来出现多处使用配置的场景，再考虑抽象为 `ConfigurationManager`。
